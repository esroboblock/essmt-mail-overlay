| 문서 방식 | 사전조사 근거를 자체 문서에 내용으로 보존 가능 | 비공개 내부 문서의 링크를 필수 참조로 삼지 않음 |

## 실제 코드에서 확인된 사실 (결정과 별개)

- ESSMT DB `emails`에 `id`, `message_id`, `naver_mail_sn`, `naver_folder_sn`, `naver_thread_id`가 정의됨.
- 현재 메일 인입 과정에서 네이버의 `mailSN`·`folderSN`을 `naver_mail_sn`·`naver_folder_sn`으로 보냄.
- 태그는 `email_tags`와 `email_tag_assignments`에 저장하며 다건 태그 조회 서비스가 있음.
- ESSMT 화면에서 `naver_folder_sn`/`naver_mail_sn` 기반 네이버 메일 원문 링크를 생성함.
- 기존 수집 확장은 별도의 MV3 `background` 서비스 워커이며, 웹메일에 태그 배지를 삽입하는 `content_scripts`는 현재 없음.
- 네이버 공급자 `threadId`는 **대화 식별 보조 자료**이며 개별 메일 고유번호와 혼동하면 안 됨.

## 설계 권고 (아직 최종 확정 아님)

1. 최초 릴리스는 **읽기 전용** 태그 표시만 제공.
2. 확장에서는 `mailSN`를 추출하고, ESSMT 서버에는 별도의 **로그인 기반 조회 API**를 추가. DB 직접 연결 금지.
3. 업무 사용자는 공용 네이버 계정으로 메일에 접근하더라도, ESSMT 정보 열람 권한은 **개인별**로 검증.
4. 목록 화면은 한 번에 다수 메일의 태그를 받는 배치 API를 이용하며 DOM 업데이트를 감시하되 불필요한 중복 요청을 제한.
5. 동일 메시지가 `전체메일`/`보낸메일함`에서 중복 DB 행으로 저장될 수 있으므로 한 화면의 표시 정책을 명시적으로 결정.
6. 개발 단계는 unpacked extension으로 확인하고, 운영 단계에는 스토어 배포와 브라우저 정책을 사용.
7. 새 확장은 기존 수집용 `X-Ingest-Token`을 절대 재사용하지 않음.

## 결정되지 않은 항목

| 항목 | 옵션 및 확인할 내용 |
| --- | --- |
| 대상 제품 정확한 범위 | `mail.naver.com` 확인, NAVER WORKS 웹메일 별도 도메인 지원 여부 검증 |
| 최초 운영 브라우저 | Edge 또는 Chrome; 현재 확정 아님 |
| 배포 스토어 | Edge Add-ons Hidden 또는 Chrome Web Store Unlisted; 양쪽 다 등록은 초기 필수 아님 |
| 스토어 계정 소유자 | 회사 명의 / 개인 명의의 권한과 장기 소유권, 실제 개발자 등록 여부 |
| ESSMT 인증 | 기존 세션의 연계 방식, 별도 로그인, 토큰 수명, 다중 PC 관리 |
| 태그 표시 위치 | 목록의 각 행, 상세 화면의 상단, 둘 다 등 UI 위치 실험 필요 |
| 식별자 획득 방법 | DOM/URL에서 `mailSN` 직접 추출 또는 네이버 내부 목록 조회와 안전하게 연결 |
| 중복 메일 처리 | 동일 메시지 여러 ESSMT 행의 태그를 병합·우선·별도 표시할지 |
| 구형 메일 처리 | `naver_mail_sn IS NULL`인 백필 메일 fallback 처리 정책 |
| 수정 기능 | 태그 추가/해제, 사용자 수정 감사, 권한과 충돌 조정은 후속 범위 |
| PC 배포 자동화 | AD / Entra 가입 여부, 각 Windows PC의 관리 권한, 원격 정책 배포 방법 |
