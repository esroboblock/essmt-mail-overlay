# 단계별 검증 계획 (초안)

이 계획은 **아직 코드 개발에 착수하지 않은 상태**를 전제로 합니다. 특히 웹메일 DOM 구조와 ESSMT 인증 방식이 확인되기 전에는 서비스 완료를 주장하지 않습니다.

## Phase 0 — 기술 가능성 확인 (read-only, 1대)

- 운영자가 정상 로그인한 대상 웹메일을 확인하고 해당 사이트의 호스트/버전 기록.
- 목록의 서로 다른 3~5개 메일에서 `mailSN`을 DOM/URL/응답으로 정확히 확인. 받은메일, 보낸메일, 검색 결과, 상세 화면 포함.
- 화면 전환/페이지 이동/스크롤 후에도 같은 메일의 `mailSN`이 일관되는지 검증.
- 현재 ESSMT DB의 실제 `naver_mail_sn` 존재율과 중복 분포를 **읽기 전용**으로 조사.
- 인증 없이 운영 데이터를 불러오지 않고, 모의 태그로 화면 표시 PoC.

**통과:** 목록과 상세에서 서로 다른 메일을 오인식 없이 구분하고, 화면 갱신 후도 태그가 중복 삽입되지 않음.

## Phase 1 — ESSMT 조회 API

- 메일 식별자 배치 입력/조회 결과 JSON 스키마 확정.
- 사용자별 ESSMT 인증·인가·세션 만료 처리 설계 및 검증.
- 0건/1건/다건 매칭, NULL serial, cross-folder 중복에 대한 명시적 API 응답.
- 한 요청에 담을 메일 수, rate limit, 접근 로그, 예외 응답 정의.
- 인증·권한·중복·대량 조회 테스트 작성.

**통과:** 권한 없는 PC/사용자는 태그를 조회할 수 없고, 정상 사용자는 지정 메일의 태그를 정확하게 받음.

## Phase 2 — 확장 UI

- MV3 `content_scripts`와 service worker 구현.
- 네이버 UI에 태그 chip 표시, 기존 메일 동작 유지, 동적 목록/상세 대응.
- 메일 식별 불명/미수집/API 실패/인증 만료를 구분하고 오류 발생 시 원본 UI는 정상 사용 가능.
- 배치/캐시/취소 처리; 불필요한 본문·첨부 열람·전송 없음.
- 2명의 직원이 같은 메일을 각각 열었을 때 ESSMT 공유 태그가 일치함을 확인.

**통과:** 1~2대 Windows PC의 동일 네이버 공용 계정에서 같은 메일을 일치하게 표시.

## Phase 3 — 배포 실험

- Chrome 또는 Edge 중 최초 브라우저와 스토어를 결정.
- 심사 테스트 방법/개인정보 설명/최소 권한 선언 완비.
- 스토어 Hidden/Unlisted 배포 및 일반 자동 업데이트 확인.
- PC 정책(강제 설치)을 적용한 3~5대 시범 운영, 설치/업데이트 버전 점검.
- 사내 지원 문서: 최초 로그인, 인증 만료, 웹메일 UI 업데이트 시 문제 보고.

**통과:** 관리자 개입 없이 동일 버전으로 업데이트되고, 설치된 확장을 통하여 태그가 조회됨.

## 이후 후보 (범위 확장 시 별도 결정)

- 웹메일에서 태그 추가·제거하고 ESSMT에 저장하는 양방향 편집
- 처리 상태, 업무 관련 엔티티 링크, 미확인/불확실 플래그 등 추가 표시
- 직원별 태그 편집 감사, 피드백 축적
- 브라우저 선택에 따라 Chrome·Edge 양쪽 스토어 동시 배포

## 주요 위험

| 위험 | 대응 |
| --- | --- |
| 네이버 UI/내부 API 변경 | DOM/라우트 식별자 PoC, 한곳의 adapter로 격리, 버전별 smoke test |
| 동일 메시지의 여러 ESSMT 행 | 단일/중복 상태 분리, 병합 여부 명시적 결정 |
| 사용자 인증 실패 | 브라우저 화면은 그대로 두고 확장 기능만 비활성/재인증 안내 |
| 직원 PC에 장기 비밀값 저장 | 수집용 토큰 복제 금지, 최소 권한·짧은 세션 설계 |
| Hidden/Unlisted를 비공개로 오인 | API 개별 인증 필수, 테스트 데이터만 심사에 사용 |
| 스토어 등록 지연 | unpacked 내부 PoC 선행, 등록 요구사항 조기 확인 |
