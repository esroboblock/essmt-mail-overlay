# 네이버 상세 태그 구현 검증

## 실제 네이버 화면에서 확보한 근거

[Overlay PR #14](https://github.com/esroboblock/essmt-mail-overlay/pull/14)에서 사용자가 열어 둔 전체메일 상세의 이전·다음 이동을 관찰했다. 같은 탭의 `/v2/read/-1/{mailSN}` 마지막 숫자가 배경 목록의 메일 행 및 상세 링크와 일치했다. `.mail_toolbar.type_read`와 `.contents_area.is_read`는 같은 부모의 자식이었다. 구현 PR에서는 선행 기록을 검토했다. 네이버 실메일을 추가로 열거나 운영 데이터를 변경하지 않았다.

상세 본문의 독립적인 SN, 실제 문서 ID의 수명, 본문 재사용 여부, URL 변경과 렌더링의 선후관계는 미확인이다. 읽기 전용 어댑터는 같은 문서에서 지원 목록을 관찰한 뒤 전체메일 상세로 이동하고, 이전 화면과 다른 상세 콘텐츠 노드가 확인될 때만 마운트한다. 상세 주소가 그대로인 동안 본문이 바뀌면 패널을 숨긴다. 이후 주소가 바뀌어도 이전 주소에서 관찰한 본문 노드가 남아 있으면 패널을 보류한다. 새 문서·직접 진입·팝업·iframe은 범위 밖이다. 실제 Naver 빌드는 Worker에서 편집 API를 차단한다.

## ESSMT API 계약 및 검증

[ESSMT PR #252](https://github.com/esroboblock/essmt/pull/252) 병합 커밋 `43594cc74ae126180d5881d75617f372e31045e1`의 `app/api/browser_overlay.py`와 연결 가이드를 기준으로 구현했다. `lookup`은 메시지 한 건, `suggestions`는 선택적 검색어, `attach`는 ID 또는 이름 한 개, `detach`는 ID를 보낸다. Worker만 대상 확인값을 메모리에 보관하고 변경 한 번에 소진한다. 탭·문서·화면 변경, Worker 종료, 5분 만료 후에는 새로 조회한다. 성공·무변경·응답 유실·404·409 후 현재 태그부터 확인하며 변경 요청을 앱에서 자동 재전송하지 않는다. 브라우저가 이미 서버로 보낸 요청은 화면이 바뀌어도 되돌릴 수 없다.

합성 Chromium E2E는 실제 확장과 HTTPS 계약 모의 서버를 사용한다. 계정 이름 변경, 문서와 화면 전환, URL과 DOM의 시간차, A → B → A, Worker 재시작, 여러 탭, 인증/권한 및 서버 오류, 변경 후 응답 유실을 검증한다. 네이버 도메인은 브라우저 안에서 합성 응답으로 대체했다.

별도의 계약 시험은 병합된 ESSMT 앱, 합성 직원의 실제 로그인, 격리 PostgreSQL 17, 루프백 HTTPS와 설치된 Overlay를 연결한다. UI에서 최근 태그 선택·부착, 새 태그 생성·부착, 중복 부착의 무변경, 해제와 재조회를 확인했다. ESSMT 자체 HTTP/MV3 회귀 15개도 통과했다. 운영 DB와 수집 서비스를 사용하지 않았다.

## 실제 환경에서 편집을 활성화하기 전

승인된 테스트 프로필에서 동일 탭의 단일 메시지 상세에 한정해 현재 렌더링된 SN과 URL을 교차 검증한다. 이전·다음, 뒤로가기, 본문 교체와 재사용, 주소와 렌더링 사이의 지연, 문서 교체를 관찰한다. 표시 이름과 ESSMT 직원 로그인으로는 동일한 네이버 계정을 증명할 수 없으므로 별도의 계정·데이터셋 연결 근거가 필요하다. 실제 화면의 패널 위치와 키보드 동작, 브라우저 쿠키 정책, 개발 프록시 경로도 확인한다.
