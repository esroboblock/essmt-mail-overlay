# #9 네이버 받은메일함과 ESSMT 검증

| 검증 범위 | 근거 |
|---|---|
| 합성 Naver DOM + 설치한 MV3 확장 + HTTPS 계약 서버 | Chromium에서 실제 Worker POST, 합성 Secure/HttpOnly/SameSite=Lax 쿠키, 태그 있음/없음·미매칭·모호함, 범위 밖 SN 제외, 401/403/422/503, 연결 실패·타임아웃·잘못된 응답을 확인합니다. |
| 실제 Naver DOM | PR #6에서 기존 Mock 확장의 80개 행 매칭과 배지 삽입을 확인했습니다. #9에서는 실제 네이버 화면에 설치하거나 재검증하지 않았습니다. |
| 실제 ESSMT 앱 + 합성 데이터 | `essmt-live.spec.js`의 데모 및 합성 Naver 경로에서 각각 실제 직원 비밀번호 로그인, Secure/HttpOnly/SameSite=Lax 쿠키 전달, DB 태그 및 빈 결과·미매칭·모호함, 로그아웃 401, 별도 무권한 직원 403을 확인했습니다. |
| 실제 Naver DOM + 실제 ESSMT 앱 | 미검증. 승인된 전용 프로필과 정확히 대응하는 테스트 데이터셋을 먼저 확인해야 합니다. 실제 SN으로 합성 DB를 임의 생성하지 않았습니다. |

합성 브라우저 테스트는 네이버 호스트 DNS를 차단하고 테스트 DOM으로 응답합니다. 연결 확인 전과 받은메일함 탭이 여럿일 때 요청을 보내지 않는지, 페이지·목록 교체와 모드 전환 시 태그가 지워지는지, 늦은 조회나 연결 확인이 무효화되는지 확인합니다. 기존 localhost Mock, Naver Mock, 데모 ESSMT, 배치 크기와 원래 UI 동작도 전체 회귀에 포함합니다.

최종 실행에서 `npm test` 38개, 격리 앱을 연결한 `npm run test:e2e` 43개가 통과했습니다. 브라우저 43개에는 실제 앱 시험 2개가 포함되며, 격리 서버 없이 실행하면 해당 2개를 건너뜁니다.

실제 앱 시험은 Windows의 Playwright Chromium과 ESSMT `5d9040e7` 소스를 사용했습니다. 앱과 새 PostgreSQL 17 컨테이너를 분리하고 마이그레이션한 뒤 합성 직원·메일·태그만 넣었습니다. HTTPS 자체서명 인증서는 임시 테스트 프로필에서만 허용했습니다. 로그인·로그아웃·조회는 실제 앱 요청이며, 관련 없는 대시보드 리소스는 테스트에서 제한했습니다. 앱 시작 시 스토리지 초기화는 생략했습니다. 운영 앱, 기존 DB, 로그인 프로필은 이 실험에 사용하지 않았습니다.

ESSMT #237의 읽기 전용 API는 병합되어 있습니다. 2026-11-10 확인 시 #239는 열린 PR이며 미병합 상태였습니다. #239의 격리 HTTP 검증 절차는 참고 자료입니다. [서버 API #237](https://github.com/esroboblock/essmt/pull/237) · [격리 검증 #239](https://github.com/esroboblock/essmt/pull/239) · [실제 네이버 Mock 검증 기록](naver-live-mock-validation.md)

## 운영 연결 전

- 전용 프로필의 네이버 테스트 계정과 ESSMT 단일 데이터셋의 출처를 확인합니다. 동일 문서·목록의 계정 전환은 DOM만으로 확인할 수 없습니다. 계정 변경 전 확장을 중지하고, 신뢰 가능한 계정 바인딩이 검증될 때까지 운영 연결을 보류합니다.
- 데이터가 있어도 중복 SN은 `ambiguous`로 두며 `folderSN`으로 후보를 선택하지 않습니다. 실제 SN·메일 내용·자격증명은 테스트 기록에 저장하지 않습니다.
- 정확한 확장 ID, 개발 ESSMT HTTPS 인증서, 서버 namespace·직원 grant, 직원 브라우저의 쿠키 정책을 확인합니다. 네이버 DOM에 렌더링한 태그 이름은 페이지 스크립트가 읽을 수 있습니다.
- ESSMT 로그아웃 및 grant 철회는 다음 조회 시 확인합니다. 주기적 조회는 30초이며 탭 복귀 또는 옵션의 재확인으로도 조회합니다. 백그라운드 타이머 제한과 이미 인증을 통과한 요청 때문에 즉시 회수는 보장되지 않습니다.
- 실제 검증에는 사용자 승인과 독립된 테스트 프로필을 사용합니다. 기존 수집 프로필, 브라우저 서비스, 운영 DB와 운영 메일은 변경하지 않았습니다.
